# النظام الوطني لإدارة مؤشرات الأداء الصحي والجودة وسلامة المرضى — اليمن

> **المرحلة الأولى (تحليل وتصميم) — بانتظار موافقتك قبل التنفيذ.**
> لم يُكتب أي كود تنفيذي بعد، ولم تُدَّعَ أي وظيفة بأنها تعمل.

## ما هذا؟
نظام من جزأين مترابطين:
1. **تطبيق سطح مكتب Windows** (Tauri + React + TypeScript) يعمل دون إنترنت داخل كل مستشفى لإدارة مؤشرات الجودة وسلامة المرضى.
2. **منصة مركزية Web** (React + FastAPI + PostgreSQL) لمتابعة أداء المستشفيات على مستوى اليمن.

مع **مزامنة موثوقة** تمنع فقدان البيانات وتكرارها.

## التنفيذ
```
backend/   الخادم الخلفي (FastAPI + PostgreSQL) — v0.15 مُختبر (226 اختباراً)
desktop/   تطبيق سطح المكتب (Tauri 2 + React + TypeScript + ECharts + SQLite) — v0.15 مُختبر (24 اختبار Rust)
portal/    المنصة المركزية (React + TypeScript + ECharts) — v0.15 مُختبر (60 اختبار واجهة)
```
- تشغيل الخادم: `bash backend/run.sh`
- اختبارات الخادم: `cd backend && ../.venv/bin/python -m pytest`
- تشغيل التطبيق: `cd desktop && npm install && npm run tauri dev`
- بناء ملفات التثبيت: `cd desktop && npm run tauri build`

> ملاحظة صريحة: بدءاً من v0.6 يعمل تطبيق سطح المكتب دون إنترنت (مخزن SQLite محلي + مزامنة تلقائية عند عودة الاتصال)، وv0.7 يضيف إبلاغ الحوادث دون إنترنت، وv0.14 يضيف إجراءات CAPA والمخاطر دون إنترنت، وv0.15 يضيف التدقيق الداخلي وخطط التحسين وخطواتها دون إنترنت. المزامنة دون إنترنت مُنفَّذة حالياً للمؤشرات والحوادث وإجراءات CAPA والمخاطر والتدقيق وخطط التحسين؛ تبقى وحدتا الوثائق والاجتماعات تُداران عبر واجهات الخادم. المساعد الذكي (v0.8) ومركز التنبيهات (v0.9) مُنفَّذان ومُختبران، لكن تحليلهما يجري على الخادم المركزي فيحتاج اتصالاً، ويعمل المساعد كاملاً دون أي نموذج ذكاء اصطناعي (النموذج اللغوي اختياري ومعطَّل افتراضياً).
