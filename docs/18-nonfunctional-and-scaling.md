# المتطلبات غير الوظيفية الوطنية والقابلية للتوسع
## النظام الوطني لإدارة مؤشرات الأداء الصحي والجودة وسلامة المرضى — وزارة الصحة العامة والسكان

**الإصدار:** 1.1 · **الحالة:** مسودة بانتظار الموافقة

---

## الشرح بلغة بسيطة
هذه الوثيقة تجيب: **كم يتحمّل النظام؟ ما سرعته؟ ما مدى توفّره؟ وما حدود أدائه على النطاق الوطني؟** أرقامها **أهداف هندسية** تُختبر فعلياً، لا وعود.

## 3. أهداف التوفّر والموثوقية (Availability)
| البُعد | الهدف |
|-------|------|
| توفّر الخادم المركزي | ≥ 99.5% (يُرفع لاحقاً) |
| **استقلال التطبيق المحلي** | **يعمل 100% دون الخادم** |
| استرجاع بعد التعطّل (RPO) | ≤ 15 دقيقة |
| زمن الاستعادة (RTO) | ≤ 4 ساعات |
| فقدان بيانات مُدخَلة | **صفر** (هدف مطلق) |

> **قاعدة جوهرية:** تعطّل الخادم **لا يوقف** المستشفيات؛ العمل المحلي مستمر.

## 4. القابلية للتوسع (Scalability)
### 4.1 محلياً
- SQLite يتحمّل ملايين السجلات لمستشفى واحد بأداء جيد (بفهارس مناسبة و WAL).
### 4.2 مركزياً
- **API أفقي:** عدة نسخ خلف موازن تحميل (stateless).
- **قاعدة البيانات:** فهارس + ترقيم صفحات + **تجميع مسبق** للوحات الثقيلة (Materialized Views).
- **تقسيم (Partitioning):** جدول قيم المؤشرات وchange_log حسب الزمن عند الحاجة.
- **كاش:** طبقة كاش للوحات (عند الحاجة).
- **تخزين المرفقات:** منفصل وقابل للتوسع.
### 4.3 المزامنة وطنياً
- دفعات محدودة، نوافذ زمنية موزّعة، ضغط، وطابور معالجة للاستيرادات الكبيرة.

## 6. الأمان كمتطلب غير وظيفي
- تشفير النقل والتخزين.
- عزل بيانات صارم (RLS + تخويل).
- تحديد معدّل وحدود استخدام.
- سجل تدقيق غير قابل للتعديل.
- **لا بيانات مرضى فردية.**
- اختبار أمني قبل كل إصدار رئيسي.

## 7. التوطين (Localization)
- **عربي RTL كامل** افتراضياً.
- أرقام عربية/لاتينية (قابل للضبط).
- تقويم ميلادي افتراضياً (مع دعم هجري اختياري لاحقاً).
- أسماء المحافظات/المستشفيات بالعربية.

## 8. قابلية الصيانة والتطوير
- **Modular Monolith** بحدود واضحة.
- ملفات مُصدَّرة بإصدار ومخطط ومسار ترقية.
- إضافة مؤشر/وحدة/مصدر بيانات عبر **واجهة مسجّلة** لا بتعديل النواة.
- كود موثّق + اختبارات تغطي المسارات الحرجة.
- لا اعتماد على شخص واحد (توثيق كامل).

## 9. قابلية النقل والتشغيل (Portability)
- نشر عبر Docker/Docker Compose.
- إعدادات عبر متغيّرات بيئة.
- سكربتات ترحيل قواعد البيانات.
- نسخ احتياطي/استعادة موثّق.

## 10. حدود واضحة (Non-Goals في المرحلة الأولى)
- لا خدمات مصغّرة (Microservices) منفصلة.
- لا بيانات مرضى فردية.
- لا تطبيق موبايل.
- لا ربط حي مع أجهزة طبية.
- لا تعلّم آلي مدرّب على بيانات حقيقية.

## 11. الاختبارات الناتجة عن هذه المتطلبات
- **اختبار حمل:** مئات المستشفيات وذروة مزامنة وطنية.
- **اختبار أداء:** كل هدف في القسم 2.
- **اختبار توفّر:** تعطّل الخادم والاستمرار المحلي.
- **اختبار استعادة:** RPO/RTO.
- **اختبار توسّع:** إضافة نسخ API وتجميع مسبق.
- **اختبار بيئي:** أجهزة ضعيفة وشبكات بطيئة.

## 12. مؤشرات المراقبة التشغيلية (KPIs)
- زمن استجابة API (p50/p95/p99).
- معدّل الأخطاء.
- حجم/تأخير المزامنة.
- عدد المستشفيات المتصلة/المتأخرة.
- زمن التجميع للوحات.
- استهلاك الموارد (CPU/ذاكرة/قرص).
