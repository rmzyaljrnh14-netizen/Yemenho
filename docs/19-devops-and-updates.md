# التشغيل والتحديثات والمراقبة (DevOps)
## النظام الوطني لإدارة مؤشرات الأداء الصحي والجودة وسلامة المرضى — وزارة الصحة العامة والسكان

**الإصدار:** 1.1 · **الحالة:** مسودة بانتظار الموافقة

---

## الشرح بلغة بسيطة
هذه الوثيقة تشرح **كيف يعمل النظام يومياً على أرض الواقع**: كيف ننشر الخادم، كيف يصل التحديث للمستشفيات، كيف نراقب المشاكل، وكيف نتعافى عند الأعطال — لأن نظاماً وطنياً بلا تشغيل جيد يتوقف.

---

## 1. البيئات (Environments)
| البيئة | الغرض | بيانات |
|-------|-------|--------|
| **تطوير (Dev)** | بناء واختبار سريع | تجريبية |
| **اختبار (Staging)** | محاكاة قريبة من الإنتاج + قبول | تجريبية |
| **إنتاج (Prod)** | التشغيل الوطني | حقيقية |
> فصل صارم: **لا بيانات حقيقية في Dev/Staging.**

## 2. النشر (Deployment)
### 2.1 الخادم المركزي (Docker Compose)
```yaml
services:
  proxy:      # Nginx/Traefik — TLS، توجيه، رؤوس أمان
  api:        # FastAPI (عدة نسخ عند الحاجة)
  worker:     # مهام خلفية (تصدير تقارير، استيراد، تجميع)
  db:         # PostgreSQL (نسخ احتياطي مجدول)
  cache:      # كاش (اختياري عند الحاجة)
  storage:    # تخزين المرفقات (MinIO/مجلد مُدار)
  backup:     # مهمة نسخ احتياطي مجدولة
```
### 2.2 خطوات النشر
1. بناء صور Docker مُوسَّمة بإصدار.
2. تطبيق **ترحيلات قاعدة البيانات** (Migrations) مع خطة تراجع.
3. نشر تدريجي (Canary/Blue-Green) لتقليل المخاطر.
4. فحص صحة (Health checks) بعد النشر.
5. توثيق الإصدار وملاحظات التغيير.

## 3. تحديث تطبيق المستشفى (Windows)
### 3.1 القناة
- **قناة تحديث موثوقة** (خادم رسمي) تنزّل الحزم.
- التحديث **موقّع** ويُتحقّق من توقيعه قبل التثبيت.
### 3.2 السلوك
- **تنزيل في الخلفية** عند توفر الإنترنت (لا يعطّل العمل).
- **تثبيت عند إعادة التشغيل** أو بموافقة المستخدم.
- **احتياطي تلقائي** قبل التحديث.
- **تراجع (Rollback)** إن فشل التحديث.
- المستشفيات بلا إنترنت: تحديث عبر حزمة فيزيائية (USB) بنفس آلية التوقيع.

## 4. الترحيلات (Database Migrations)
- كل تغيير مخطط = ملف ترحيل مُرقّم ومُختبر.
- **توافق خلفي** حيث أمكن (إضافة أعمدة لا حذفها فوراً).
- **خطة تراجع** لكل ترحيل خطير.
- تُختبر على Staging أولاً بنسخة من البيانات.
- التطبيق المحلي يطبّق ترحيلاته عند التحديث بأمان.

## 5. النسخ الاحتياطي والاستعادة
### 5.1 محلياً (المستشفى)
- نسخة يومية تلقائية (قاعدة + مرفقات) **مشفّرة**.
- الاحتفاظ بعدة نسخ (دورات).
- استعادة بتحقق من السلامة أولاً.
### 5.2 مركزياً
- نسخ PostgreSQL مجدولة (WAL للأرشفة المستمرة).
- **نسخة بعيدة** في موقع آخر (حماية من الكوارث).
- نسخ التخزين.
- **اختبار استعادة دوري** (نسخة لا تُختبر = غير موثوقة).
### 5.3 الأهداف
- RPO ≤ 15 دقيقة، RTO ≤ 4 ساعات.

## 6. المراقبة (Monitoring)
### 6.1 ما نراقبه
| المكوّن | المؤشرات |
|--------|----------|
| API | زمن الاستجابة، معدّل الأخطاء، الطلبات/ثانية |
| قاعدة البيانات | الاستعلامات البطيئة، الاتصالات، الحجم |
| المزامنة | حجم/تأخير، أخطاء، مستشفيات متأخرة |
| الخادم | CPU/ذاكرة/قرص/شبكة |
| التطبيق المحلي | أخطاء، فشل تحديث |
| الأمان | محاولات دخول فاشلة، وصول مرفوض |
### 6.2 التنبيهات
- تنبيه فوري عند: تعطّل خدمة، ارتفاع الأخطاء، توقف مستشفى عن الإرسال، امتلاء القرص، فشل نسخ احتياطي.
- قنوات: بريد/رسائل/لوحة.
### 6.3 لوحات تشغيل
- **لوحة صحة النظام** (معدّلات، أخطاء، زمن استجابة).
- **لوحة المزامنة الوطنية** (المتصلون، المتأخرون، الحجم).
- **لوحة الأمان** (محاولات فاشلة، وصول مرفوض).

## 7. التسجيل (Logging)
- **منظّم (Structured)** بصيغة موحّدة.
- **لا أسرار ولا بيانات شخصية** في السجلات.
- مستويات: خطأ/تحذير/معلومة/تصحيح.
- **ربط الطلبات** عبر `X-Request-Id` لتتبّع أي مشكلة.
- دوران السجلات وحجم محدود.

## 8. إدارة الحوادث (Incident Management)
```
كشف → تصنيف الخطورة → احتواء → معالجة → استعادة → تحليل السبب → درس مستفاد
```
- **أولويات:** تعطّل كامل > فقدان بيانات > خطأ وظيفي > بطء.
- **تواصل** مع المستشفيات المتأثرة.
- **توثيق** كل حادث ودرسه.

## 9. الصيانة الدورية
| الدورية | العمل |
|--------|-------|
| يومي | مراجعة التنبيهات، فشل النسخ |
| أسبوعي | مراجعة الأخطاء، المزامنة المتأخرة |
| شهري | تحديث أمني، مراجعة أداء، مراجعة سجل التدقيق |
| ربع سنوي | اختبار استعادة، مراجعة صلاحيات |
| سنوي | مراجعة سياسات، تحديث تبعيات رئيسية |

## 10. الفريق التشغيلي (Ops)
- **مكتب دعم وطني** يستقبل مشاكل المستشفيات.
- **فريق فني مركزي** للأعطال التقنية.
- **مدربون** في المحافظات.
- **قنوات دعم** واضحة (هاتف/رسائل/نموذج).
- **مستويات دعم (Tiers):** L1 (أساسي) → L2 (فني) → L3 (تطوير).

## 11. إدارة الإصدارات (Release Management)
- **ترقيم دلالي** (Major.Minor.Patch).
- **ملاحظات تغيير** لكل إصدار.
- **نافذة إصدار** محدّدة (تفادي أوقات الذروة).
- **تراجع** جاهز إن فشل النشر.

## 12. قائمة تحقق ما قبل النشر (Pre-Release Checklist)
- [ ] كل الاختبارات تمر (وحدة/تكامل/E2E/مزامنة/أمان).
- [ ] ترحيلات مُختبرة على Staging.
- [ ] نسخة احتياطية حديثة موجودة.
- [ ] خطة تراجع جاهزة.
- [ ] ملاحظات تغيير مكتوبة.
- [ ] فحص صحة ما بعد النشر.
- [ ] إبلاغ المستشفيات إن كان التغيير مؤثراً.
