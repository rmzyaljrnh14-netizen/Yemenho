# دراسة الجدوى
## النظام الوطني لإدارة مؤشرات الأداء الصحي والجودة وسلامة المرضى في اليمن

**الإصدار:** 1.0 — المرحلة الأولى (تحليل) · **الحالة:** مسودة بانتظار الموافقة

---

## الشرح بلغة بسيطة (اقرأ هذا أولاً)
دراسة الجدوى تجيب على سؤال واحد: **هل يستحق هذا المشروع أن نبنيه فعلاً؟**
نفحص خمسة أمور: هل هو **مطلوب**؟ هل هو **ممكن تقنياً**؟ هل سيعمل **عملياً** في ظروف اليمن؟ كم **سيكلّف**؟ وما **المخاطر**؟
الخلاصة في نهاية الوثيقة، وبدون تجميل.

## 1. خلفية المشروع ومبرره

### 1.1 المشكلة
القطاع الصحي اليمني يعاني من ضعف في قياس الجودة ومتابعة الأداء:
- لا توجد **منصة موحّدة** تجمع مؤشرات الجودة وسلامة المرضى من المستشفيات وتقارن بينها مركزياً.
- البيانات تُجمع يدوياً وعلى ورق أو بجداول Excel متفرقة، فتُفقد وتتأخر ولا تُقارن.
- لا يوجد تتبّع منهجي للحوادث والأخطاء الطبية وتحليل أسبابها الجذرية (RCA) والإجراءات التصحيحية (CAPA) بشكل موحّد.
- انقطاع الكهرباء والإنترنت يجعل أي نظام يعتمد على الاتصال الدائم غير عملي.

### 1.2 الوضع القائم (ما يجب ألا نكرّره)
- **منظومة المعلومات الصحية الوطنية DHIS2** قائمة وتُدار من وزارة الصحة العامة والسكان (الإدارة العامة للمعلومات والبحوث) بدعم منظمة الصحة العالمية واليونيسف وشركاء مثل HISP-MENA. تُستخدم لجمع بيانات الخدمات والإبلاغ الدوري (التحصين، صحة الطفل، الأمراض غير السارية، الصحة النفسية، التغذية…).
- **منظمة الصحة العالمية** تدعم اعتماد **الحد الأدنى من معايير الجودة وسلامة المرضى** وتعمل على صياغة أول **استراتيجية وطنية لجودة الرعاية** في اليمن.
- توجد **استراتيجية صحية وطنية 2010–2025** و**استراتيجية التعاون القُطري لمنظمة الصحة العالمية مع اليمن 2024–2025**.

> **النتيجة المهمة:** النظام المقترح **مكمّل لا منافس**. وظيفته أن يجلب طبقة الجودة وسلامة المرضى والقياس التفصيلي داخل المستشفى إلى منظومة وطنية قائمة، ويرسل خلاصة قابلة للتكامل مع DHIS2 — لا أن يعيد بناء جمع بيانات الخدمات.

### 1.3 الفرصة
- وجود إرادة وطنية ودعم دولي للجودة وسلامة المرضى.
- وجود مستشفيات تعليمية ومرجعية (مثل هيئة المستشفى الجمهوري التعليمي بصنعاء) يمكن أن تكون نقطة انطلاق تجريبية.
- غياب أداة مخصّصة لإدارة جودة المستشفى محلياً يعني أن الحاجة غير مخدومة.

### 1.4 الملكية والنطاق المستهدف (محدَّث)
- **الجهة المالكة:** **وزارة الصحة العامة والسكان** (الإدارة العامة للجودة بالتنسيق مع الإدارة العامة للمعلومات والبحوث). التفصيل في الوثيقة 11.
- **النطاق:** **ربط كل مستشفيات اليمن** تدريجياً على **موجات نشر واقعية** (الوثيقة 12)، مع تصميم يتحمّل النطاق الوطني الكامل (مئات المستشفيات، 22 محافظة) من اليوم الأول.
- **الواقعية:** الربط الشامل رحلة متدرّجة تشمل: مستشفى → محافظة رائدة → ثلاث محافظات متنوعة → تعميم وطني، مع دعم طبقات اتصال مختلفة (من المتصل الدائم إلى المنفصل تماماً بنقل فيزيائي).

## 2. الجدوى المطلوبية (هل نحن بحاجة إليه؟)

| المؤشر | التقييم |
|-------|---------|
| حاجة المستشفى لإدارة جودة وسلامة مرضى منظمة | **عالية** — لا توجد أداة موحّدة |
| حاجة الإدارة المركزية للمقارنة والمتابعة | **عالية** — المتابعة حالياً يدوية ومتقطّعة |
| وجود حل بديل جاهز يغطي الحاجة | **منخفض** — DHIS2 لا يغطي جودة القسم وسلامة المريض بتفصيلها |
| القيمة المضافة إذا نُفّذ بنجاح | **عالية** — قرارات مبنية على بيانات، وكشف مبكر للمشكلات |

**الحكم:** الجدوى المطلوبية **قوية**، بشرط إدارة واضحة للموافقات الرسمية.

## 3. الجدوى التقنية

### 3.1 لماذا التقنيات المختارة مناسبة
- **Tauri 2 + React + TypeScript:** تطبيق Windows خفيف الحجم (أصغر بكثير من Electron)، يعمل دون إنترنت، يدعم واجهات RTL/عربية جيداً، ويستخدم WebView الموجود في النظام (لا يستهلك موارد كبيرة على أجهزة ضعيفة).
- **SQLite:** قاعدة بيانات محلية ملف واحد، بلا خادم، مثالية للعمل دون إنترنت، وتدعم المعاملات (Transactions) التي تضمن عدم تلف البيانات عند انقطاع الكهرباء.
- **FastAPI (Python):** سريع، موثّق تلقائياً، مناسب لواجهات REST، وفيه منظومة غنية للتحقق من البيانات.
- **PostgreSQL:** قاعدة بيانات مركزية قوية، تدعم **أمان مستوى الصف (RLS)** لعزل بيانات المستشفيات، وتدعم النسخ الاحتياطي والاستعادة المتقدم.
- **Docker:** نشر متكرر وموثوق على أي خادم.

### 3.2 أعقد جزء تقنياً: المزامنة
المزامنة بين قاعدة محلية وقاعدة مركزية **دون فقدان أو تكرار** هي المهمة الأصعب، وتشمل: معرّفات فريدة، طوابير تغييرات، اكتشاف التعارض، وسجلات تدقيق. **التقييم: ممكنة تقنياً**، ونعالجها بتصميم مفصّل في الوثيقة رقم 7 واختبارات محاكاة لانقطاع الاتصال.

### 3.3 العوائق التقنية المتوقعة
| العائق | الحل المقترح |
|-------|--------------|
| أجهزة ضعيفة أو قديمة | Tauri خفيف + واجهات بسيطة + عدم تحميل صور كبيرة |
| انقطاع الكهرباء المفاجئ | كتابة ذرّية على SQLite (WAL) + نسخ احتياطي دوري |
| إنترنت بطيء/متقطع | مزامنة تزايدية (ترسل التغييرات فقط) ودفعات صغيرة قابلة للاستئناف |
| بيانات حساسة | تشفير أثناء النقل (TLS) وأثناء التخزين عند الحاجة |
| الويندوز المتنوّع (7/10/11) | نحدّد الحد الأدنى المدعوم (نوصي Windows 10 وما بعده) |

## 4. الجدوى التشغيلية (هل سيعمل في أرض الواقع؟)

| العامل | التقييم | المعالجة |
|-------|---------|----------|
| الكهرباء المتقطعة | **مشكلة حقيقية** | العمل محلياً دون كهرباء طويلة، وحفظ آمن، وأجهزة UPS إن أمكن |
| الإنترنت المتقطع | **مشكلة حقيقية** | النظام يعمل كاملاً دون إنترنت ويزامن لاحقاً |
| مستوى مهارات المستخدمين | **متوسط إلى منخفض** | واجهة عربية بسيطة + تلميحات + دليل استخدام + تدريب |
| مقاومة التغيير | **متوقّعة** | إشراك المستخدمين مبكراً + تجربة تجريبية في مستشفى واحد |
| الصيانة والدعم | **يحتاج جهة مسؤولة** | فريق دعم مركزي + تحديثات آلية |
| التزام المستشفيات بالإدخال | **حرج للنجاح** | ربط الإدخال بالاعتماد الرسمي + تقارير متابعة التأخير |

**الحكم:** الجدوى التشغيلية **مشروطة** بنجاح التجربة التجريبية وإدارة التغيير والتدريب.

## 5. الجدوى الاقتصادية (التكلفة والعائد)

> **تنبيه:** الأرقام **تقديرية** وتُضبط بعد الاتفاق على النطاق. لا تُعد عرض سعر.

### 5.1 التكاليف لمرة واحدة (تقديرية)
| البند | الوصف | تقدير نسبي |
|------|-------|-----------|
| التطوير (تطبيق سطح مكتب) | Tauri/React/TS | كبير |
| التطوير (منصة مركزية + خادم) | React + FastAPI + PostgreSQL | كبير |
| المزامنة والذكاء الاصطناعي | وحدات معقدة | متوسط |
| التصميم وتجربة المستخدم + التوطين | واجهات عربية RTL | متوسط |
| الاختبارات والأمان | وظيفي + أمني | متوسط |
| التغليف والتثبيت | حزمة Windows + تحديثات | صغير |
| التدريب والتوثيق | أدلة عربية + ورش | متوسط |

### 5.2 التكاليف التشغيلية (سنوية)
| البند | الوصف |
|------|-------|
| الخادم والاستضافة | سحابة أو جهاز داخل اليمن |
| قاعدة البيانات والنسخ الاحتياطي | مساحة تخزين + نسخ احتياطي بعيد |
| الصيانة والدعم | فريق دعم |
| تكلفة الذكاء الاصطناعي | حسب الاستخدام (يمكن تشغيله محلياً لتقليل التكلفة والخصوصية) |
| التدريب المستمر | مستخدمون جدد |

### 5.3 العائد (غير النقدي أساساً)
- **قرارات أفضل:** كشف مبكر لتدهور مؤشرات الجودة قبل أن تتحول إلى حوادث.
- **تقليل الأخطاء الطبية:** تتبّع الحوادث و RCA يقلل التكرار.
- **امتثال وطني ودولي:** دعم تطبيق معايير الجودة وسلامة المرضى الوطنية.
- **توفير الوقت:** إلغاء التجميع اليدوي والتقارير الورقية.
- **قابلية القياس:** إثبات التحسّن بالأرقام أمام الجهات المانحة.

**الحكم:** الجدوى الاقتصادية **معقولة** إذا بدأنا صغيراً (مستشفى واحد) ووسّعنا تدريجياً؛ العائد أساسه **تحسين الجودة** لا الربح.

## 6. الجدوى القانونية والتنظيمية

| الجانب | الوضع | المطلوب |
|-------|-------|---------|
| ملكية البيانات | بيانات المستشفى ملك للجهة الصحية | اتفاقية ملكية ومعالجة بيانات |
| خصوصية بيانات المرضى | النظام **لا يجمع بيانات شخصية للمريض** (مؤشرات مُجمّعة) | تأكيد هذا التصميم وتوثيقه |
| موافقات الربط بين المستشفيات | غير متوفرة تلقائياً | موافقة وزارة الصحة/الجهة المعنية |
| الصلاحيات الرسمية للاعتماد | تحتاج تحديد | قرار بتحديد من يعتمد النتائج |
| التوافق مع DHIS2 | مطلوب مستقبلاً | نقاط تبادل بيانات متوافقة |

> **قيد صريح:** الربط الفعلي بين المستشفيات **يتطلب موافقة الجهات الصحية المعنية وتعاون المؤسسات**، وهو أمر خارج سيطرة الفريق التقني.

## 9. خطة الاستدامة
- **جهة مالكة واضحة** تتحمّل الاعتماد والصلاحيات.
- **فريق دعم مركزي** مدرّب + تحديثات آلية.
- **تدريب مدربين** داخل كل مستشفى.
- **توثيق كامل** (فني + مستخدم) لتمكين نقل المعرفة.
- **بنية قابلة للتوسع** تسمح بإضافة مستشفيات دون إعادة بناء.

## 10. الخلاصة والقرار

| المحور | الحكم |
|-------|-------|
| الجدوى المطلوبية | ✅ قوية |
| الجدوى التقنية | ✅ ممكنة (المزامنة هي التحدي الأكبر) |
| الجدوى التشغيلية | ⚠️ مشروطة بالتجربة والتدريب |
| الجدوى الاقتصادية | ✅ معقولة بالبدء التدريجي |
| الجدوى التنظيمية | ⚠️ تحتاج موافقات رسمية |
| المخاطر الكلية | 🟡 متوسطة، قابلة للإدارة |

### **التوصية النهائية: المضي قدماً بنموذج تدريجي**
1. ابدأ بمستشفى واحد تجريبي (هيئة المستشفى الجمهوري التعليمي بصنعاء).
2. أثبت الجدوى عملياً (بيانات حقيقية + مزامنة + تقارير).
3. وسّع إلى 2–3 مستشفيات لاختبار الربط والصلاحيات.
4. ثم التوسع الوطني بعد نجاح التجربة.

**لا يُوصى بالتنفيذ الكامل الوطني من البداية** — التدرّج يقلل المخاطر ويثبت القيمة قبل التوسع.

1. منظمة الصحة العالمية — صفحة اليمن: الدعم في الجودة وسلامة المرضى واعتماد الحد الأدنى من معايير الجودة — <https://www.who.int/yemen>
2. منظمة الصحة العالمية — تحسين جودة الرعاية: مسار اليمن نحو التغطية الصحية الشاملة — <https://www.emro.who.int/yem>
3. منظمة الصحة العالمية — استراتيجية التعاون القُطري مع اليمن 2024–2025.
4. الاستراتيجية الصحية الوطنية لليمن 2010–2025 (WHO/OMS Extranet).

7. ويكيبيديا (معلومات عامة عن نظام الصحة في اليمن ومستوياته الأربعة) — <https://en.wikipedia.org/wiki/Health_in_Yemen>
