# الخادم الخلفي (Backend) — v0.6

النظام الوطني لإدارة مؤشرات الأداء الصحي والجودة وسلامة المرضى — وزارة الصحة العامة والسكان.

## ما تم تنفيذه فعلياً (ومُختبر)

### v0.1
- **قاعدة البيانات (PostgreSQL 16):** الهيكل المؤسسي (وزارة → محافظة → مديرية → مستشفى)، الأقسام، المستخدمون، الأدوار، الصلاحيات، سجل التدقيق.
- **عزل البيانات (Row-Level Security):** كل مستشفى يرى بياناته فقط؛ المحافظة ترى مستشفياتها؛ الإدارة المركزية ترى الكل.
- **المصادقة:** تسجيل دخول برموز JWT + تجزئة كلمات المرور بـ Argon2 + قفل الحساب بعد محاولات فاشلة.
- **الصلاحيات:** 8 أدوار و12 صلاحية، مع حرّاس على كل نقطة حساسة.
- **سجل التدقيق:** كل إجراء حساس يُسجَّل (من، ماذا، متى).

### v0.4
- **مكتبة المؤشرات الوطنية:** 25 مؤشراً في تعريفات أولية (اسم، رمز، تعريف، هدف، طريقة القياس، وحدة، مصدر بيانات، دورية، جهة مسؤولة، قيمة مستهدفة، حدود مقبولة، اتجاه التحسن).
- **أنواع حساب متعددة:** نسبة، معدل، نسبة مئوية، عدد، متوسط، مجموع، إدخال مباشر — ليست كلها بسطاً ومقاماً.
- **اتجاه التحسن:** ارتفاعه أفضل / انخفاضه أفضل / نطاق مستهدف، ويُطبَّق في التقييم والاتجاه.
- **إسناد المؤشرات** لكل مستشفى و/أو قسم، مع إمكانية تجاوز القيمة المستهدفة لكل إسناد.
- **فترات التقارير** (شهرية/ربعية/سنوية) وقيم المؤشرات مع الحساب التلقائي والتقييم.
- **دورة العمل:** مسودة ← إرسال للمراجعة ← مراجعة ← اعتماد، أو إعادة للتعديل. البيانات المُرسلة/المعتمدة **مجمّدة** ولا تُستبدل دون صلاحية.
- **سجل التعديلات:** كل إنشاء/تعديل/حذف لقيمة يُسجَّل (القيمة قبل وبعد).
- **87 اختباراً تمر جميعها**، منها اختبارات الحساب والعزل الأمني وعدم قابلية تعديل المعتمد.

### v0.5
- **لوحة وطنية مجمّعة:** عدد المستشفيات، المُرسِلة، المؤشرات المحسوبة والمحققة، ونسبة تحقيق الأهداف.
- **مقارنة المستشفيات والمحافظات:** ترتيب حسب نسبة تحقيق الأهداف، والأداء المجمّع لكل محافظة.
- **تقرير مستشفى واتجاه مؤشر:** كل مؤشرات مستشفى في فترة مع التقييم والاتجاه، وسلسلة زمنية شهرية.
- **متابعة المتأخرين:** قائمة المستشفيات التي لم تُرسل بياناتها للفترة المطلوبة.
- **تصدير Excel وPDF بالعربية:** ملفات فعلية باتجاه RTL وتشكيل حروف عربي (خط Noto مضمَّن).
- **حماية بصلاحية `report.view`** مع احترام نطاق المستخدم (عزل RLS) في كل نقطة تقارير.

### v0.6 — المزامنة والعمل دون إنترنت (الجزء الخادمي)
- **سجل التغييرات المتسلسل (`change_log`):** كل كتابة على الخادم (فترة، قيمة، مؤشر) تُسجَّل بترتيب عالمي (`server_seq`)، فيسحب كل جهاز ما فاته فقط من نقطة توقّفه.
- **منع التكرار (Idempotency):** جدول `sync_idempotency` يخزّن نتيجة كل عملية بـ `op_id`؛ إعادة الإرسال لا تُنشئ نسخة ثانية.
- **دفع التغييرات (Push):** `POST /api/v1/sync/push` يستقبل دفعة عمليات محلية ويطبّقها بترتيب آمن، ويعيد نتيجة كل عملية (`applied` / `conflict` / `rejected`).
- **كشف التعارض (Conflict):** إذا كانت مراجعة الخادم (`rev`) أحدث من مراجعة العملية المحلية (`base_rev`)، لا تُستبدل البيانات؛ تُسجَّل الحالة في `conflict_log` وتُعاد نسخة الخادم.
- **حماية المعتمد:** لا يمكن تعديل قيمة في فترة حالتها `submitted`/`reviewed`/`approved` عبر المزامنة؛ تُرفَض العملية برسالة عربية واضحة.
- **سحب التغييرات (Pull):** `GET /api/v1/sync/pull?since=…` يعيد التغييرات بعد المؤشّر مع `has_more` للصفحات الكبيرة.
- **التهيئة الأولى (Bootstrap):** `POST /api/v1/sync/bootstrap` يمنح الجهاز مكتبة المؤشرات، الإسنادات، الأقسام، والفترات للعمل دون إنترنت لاحقاً.
- **حالة الجهاز:** `GET /api/v1/sync/status` تعيد آخر مؤشّر مزامنة وعدد التغييرات المعلّقة على الخادم.
- **العزل والصلاحيات:** كل عمليات المزامنة تعيد تطبيق RLS (لا عبور بين المستشفيات)، وتتطلب صلاحية كتابة (المستخدم للقراءة فقط يُرفض بـ 403).
- **99 اختباراً تمر جميعها**، منها 12 اختباراً جديداً للمزامنة.

## التشغيل

```bash
# 1) قاعدة البيانات (Docker)
docker run -d --name yhq-postgres \
  -e POSTGRES_USER=yhq -e POSTGRES_PASSWORD=yhq_dev_pw -e POSTGRES_DB=yhq \
  -p 5432:5432 postgres:16-alpine

# 2) البيئة والتبعيات
python3 -m venv .venv
./.venv/bin/pip install -r backend/requirements.txt

# 3) التشغيل (يرحّل القاعدة، يزرع بيانات تجريبية، ثم يشغّل الـ API)
bash backend/run.sh
```

الـ API على `http://127.0.0.1:8000` — والوثائق التفاعلية على `/docs`.

## الاختبارات

```bash
cd backend && ../.venv/bin/python -m pytest
```

## ملاحظات أمنية مهمّة (تعلّمناها بالتنفيذ)

1. **RLS لا يعمل مع مستخدم فائق (superuser)** حتى مع `FORCE ROW LEVEL SECURITY`. لذلك التطبيق يعمل بدور `yhq_app` (NOSUPERUSER, NOBYPASSRLS)، والترحيلات فقط تستخدم الدور الفائق.
2. **نطاق المحافظة لا يُشتق من نطاق المستشفى** — وإلا تسرّبت بيانات مستشفيات المحافظة كلها لمستخدم مستشفى واحد.
3. رسائل الأخطاء **لا تكشف تفاصيل داخلية**.


## ما لم يُنفَّذ بعد (بصراحة)

- **الصائغ اللغوي للنموذج** لم يُشغَّل مع مزوّد حقيقي في هذه البيئة (مُختبَر بمُختبِر وهمي).
- **مزامنة بقية وحدات الجودة** (CAPA، المخاطر، التدقيق…) — المزامنة دون إنترنت مُنفَّذة للمؤشرات والحوادث.
- **إشعارات خارجية (بريد/رسائل) أو دفع لحظي** — مركز التنبيهات يحسب التنبيهات عند
  فتحه (منها تنبيهات المزامنة منذ v0.13) ولا يدفعها إلى خارج النظام.

لا ندّعي أن أي جزء منها يعمل قبل تنفيذه واختباره.
